# Future FDI Generation Approach

## Scope

This note documents the recommended direction for a future FDI file generation refactor. It does not change the current Power Apps app, Power Automate flows, SharePoint lists, folio generation, or business states.

## Recommendation

The FDI workbook should not be generated by filling Excel row by row directly from Power Automate. That approach is fragile, slow to maintain, and hard to validate as the FDI template evolves.

Future generation should be based on a script or template-driven process that receives structured data from the app or flow and produces the Excel file in one controlled step. The structured payload should contain the quotation header, client data, selected systems, technical details, parts lists, and any attachments or references needed by the final workbook.

Power Automate should act as the orchestrator: collect inputs, call the generation process, store the output, notify users, and handle approval or delivery steps. It should not own the detailed workbook-building logic.

## Benefits

- Reduces silent formatting and mapping errors in the generated FDI.
- Keeps the Excel template easier to version and test.
- Makes future changes to systems, sections, and columns less risky.
- Separates orchestration from document generation logic.
